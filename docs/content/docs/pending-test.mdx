# 验收记录

本页记录当前分支的实际验收结果，以及仍然需要在生产环境完成的边界验证。代码存在、测试合同存在、自动测试通过、浏览器交互通过和真实 Provider/媒体质量通过必须分别说明，不能互相替代。

## 画布图片设置与扩展编辑

当前工作区已调整画布生成节点的参数入口：

- 图片设置按“比例”和“清晰度”分组显示，`16:9(2k)`、`16:9(4k)` 等组合值不再作为比例选项；底部摘要改为 `16:9 / 2K` 这类独立信息；
- 切换比例会保留当前清晰度，若目标比例没有该清晰度，则选择该比例实际支持的档位；模型需要的像素尺寸或独立清晰度参数仍按既有能力配置提交；
- 图片和视频的扩展文本窗口不再显示设置按钮，参数入口只保留在外部节点编辑区。

已完成前端生产构建与参数映射的 Node 断言检查；由于当前环境没有 Bun 运行时，新增的 Bun 单元测试尚未实际执行。

待用户验收：

- 在图片节点打开设置，确认比例与清晰度分开显示，选择 `1K` / `2K` / `4K` 后外部摘要和实际生成画幅一致；
- 在图片或视频节点打开“放大编辑”，确认底部不再出现比例、清晰度、分辨率或时长设置按钮，关闭后外部节点仍可正常打开设置。

## 视频结果回到画布与渠道目录同步

当前工作区已加入两项待人工验收的实现：

- 影视 `canvas_video` Task 成功后，画布会查询 Task 的已公开结果，并立即创建稳定的
  `film-generation-result:<taskId>` 视频节点；该节点继续使用现有画布播放器，而不是影视信息卡。
  已人工移动、改名或调整尺寸的结果节点会被保留。结果连线以 Task 输入中的实际生成节点为准；
  若该节点已经删除，不会连接到其他节点，系统生成的孤立连线会被清理。
- 管理员拉取系统渠道目录时会合并标准 `/models` 与视频网关的 `/health` 目录。`/models`
  不可用但 `/health` 可用时仍能发现视频模型及其时长、画幅和分辨率能力。新发现模型始终为
  “未启用、未定价、零价格”；上游的 `pointsCost` 不会成为对用户的积分价格，已有模型的启用、
  定价和能力配置也不会被拉取动作覆盖。

浏览器即时节点只是 Task 级展示加速，不会伪造 `GenerationAttempt`、`ProviderJob`、`Result`
或 `Resource` ID。刷新后仍以服务端的 Canvas Projection Patch 和执行事实链为准。

本轮修复了服务端结果投影的来源定位：Result Patch 的 `nodeId` 只代表稳定结果节点，生成请求节点
必须由同一 Task 的服务端 Task Patch 确认；缺少、重复或目标版本不一致时均拒绝投影，避免连接到
同一画布中的错误生成节点。后端全量 `go test ./... -count=1`、Web 93 个既有测试、6 个视频结果投影/
渠道策略定向测试及 `bun run build` 均已通过，没有调用真实 Provider。浏览器已确认登录页可加载且
控制台无告警或错误；当前浏览器没有本地登录态，因此 Film 项目、Spatial 编辑器和结果节点播放仍属
下列登录态人工验收范围。

待用户验收：

- 管理员完成某个视频模型的协议、能力、积分价格和启用设置后，以非生产项目提交一条明确确认费用的
  视频任务；确认成功视频在不刷新画布时出现、可播放，并在刷新后保持同一结果节点及连线；
- 删除或替换生成请求节点后，让已完成 Task 的页面轮询一次，确认不会产生连到错误节点的结果连线；
- 管理员再次拉取渠道目录，确认新上游模型只出现在管理员待配置列表，普通用户在未定价或未启用前
  看不到、也无法提交；
- 管理员启停或调价后，让一个已登录的普通用户页面回到前台，确认系统模型目录会立即刷新；持续停留时
  最多五分钟也会刷新。刷新失败时应继续使用已缓存目录，而不暴露系统渠道凭证；
- 管理员和自定义渠道页面点击“测试模型”后，确认只有在第二次明确确认后才会向上游发送真实请求；
  视频确认文案应明确默认测试时长、可能的供应商费用以及不创建平台用户任务/积分订单的边界；
- 真实视频仍不得在未确认渠道计费、并发额度、资源下载鉴权和退款策略前作为生产验收结论。

## 场景空间连续性系统

当前工作区已加入场景级 `scene_asset_pack` 与 `spatial_continuity_gate`，包括 Scene Manifest、拓扑图、平面图、固定/可移动锚点、机位、剧情驱动视角覆盖、室内外 Look Card、证据、必经路径和权威冲突。Gate 只有 `PASS`、`UNCERTAIN`、`FAIL`、`NEEDS_YOU` 四种状态，关联场景的 Generation Request 只有在 Gate 为 `PASS` 时才能进入 Provider 路由和原子提交。

待用户验收：

- 用黑市诊所完整空间包确认 `PASS`，并确认场景节点 `Spatial` 标签可结构化编辑 Pack、显示 Pack/Gate 版本并将问题定位到对应输入区；
- 分别制造门或固定锚点漂移、缺视角、缺证据和权威冲突，确认四种状态及中文原因；
- 在失败草稿后恢复已锁定布局，确认系统以最近一次 `PASS` 为基线并重新开放生成；
- 在两个页面并发保存同一场景，确认旧页面收到版本冲突而不是覆盖新版本；
- 场景 Gate 更新后尝试提交旧任务草稿，确认不创建 Task、不预留积分、不调用 Provider。

完整合同见 `docs/production-canvas/scene-spatial-contract.md`。

新增黑市诊所 Prompt 编译、视角歧义阻断和空间版本漂移测试。当前没有真实成片诊断执行器，
`FIXED_PROP_DRIFT` 等诊断码仍是合同映射/人工 QC 边界，不能当作自动视觉检测结果。

当前工作树已重新运行后端全量 `go test ./... -count=1`、Web 93 个既有测试、6 个视频结果投影/渠道策略定向测试和生产构建并通过。黑市诊所 Fixture 覆盖诊所内部、门、门口、外墙、街角、主街和右侧街道延伸，包含固定垃圾桶、墙面标志、管线、8 个 Camera/View 与完整出门路径；Fixture 中的资产/证据 ID 仅用于结构测试，没有调用图片或视频模型。

## Film Provider Gateway 执行事实链

当前工作区已加入：

- Scene Asset Pack 保存必须提交 `expectedVersion`；同一版本被另一个页面先保存后，旧页面提交必须返回 `409`，且不能追加 Pack/Gate 版本；
- 删除项目时，挂在领域项目、关联 Canvas、GenerationAttempt 或 ProviderJob 上的活动/不确定执行必须阻止删除；
- Film Task 显式保存 `domainProjectId` 与 `canvasId`，迁移从最新 GenerationAttempt 回填旧影视任务，旧 `projectId` 仅保留兼容；
- 原子提交同时创建 queued `Task`、queued `GenerationAttempt`、可选计费预留和 `CanvasProjectionPatch`；
- Worker 领取、租约恢复、失败、取消与 Retry 的 Attempt 编号和状态事务；
- 失效 Worker 的进度、终态和完成写入隔离，以及迟到 Provider 观察仍归原 Attempt；
- Attempt 作用域的 `ProviderJob`，以及 API 调用状态和取消状态归一化；
- Task 成功、Attempt 成功与 `Result(kind = film_generation_result)` 同事务写入；
- `GET /projects/:projectId/film-generation-requests/:artifactId/executions` 只读执行历史；
- Canvas 读取时投影 Task/Attempt/ProviderJob/Result ID，保存时剥离客户端运行时 ID；
- 成功链、上游状态不明、排队即取消后 Retry、租约恢复、迟到观察、原子回滚和投影边界测试合同。

## 人物一致性验收计划（图片专用）

下一轮只验证图片，不触发视频或未定价模型。测试必须固定同一角色版本、同一画风、同一
`1:1` 尺寸和单张输出，并把每次请求的 Task ID、模型、耗时、费用和结果资源保存到验收表。

建议的三张受控变体：

1. 中景正面/三分之二侧面：验证脸部、发型、服装和主道具锁定；
2. 过肩或侧面反应：验证轮廓、体态和视线变化不会造成换脸；
3. 同场景情绪变化：验证表情和动作变化不会破坏角色身份或场景连续性。

每张图由人工按 0–2 分记录五项：身份特征、服装/道具、场景连续性、提示词遵循、结构缺陷。
三张合计至少 24/30 且没有“换脸、严重肢体错误、场景完全漂移”才算通过；这只是业务验收
门槛，不等同于自动视觉质量证明。当前基准模型为 `gpt-image-2`，本组预算上限建议为 3 积分，
发起前必须再次确认费用。

低价模型候选（如 `gpt-image-2-lite`）只有在管理员完成协议、能力、价格和限流配置后，才可
使用同一组提示词做 A/B；未通过基准前不得开放给普通用户。

## 人物一致性验收结果（2026-08-15）

按上述方案完成了 3 张受控图片，均使用同一个短剧镜头、同一组文本人物锚点、`gpt-image-2`、
`1:1`、单张输出；没有调用视频或未定价模型。每次提交前都在执行面板确认目录价 1 积分/次，
三笔账单均为 `settled`，实际扣除 1,000,000 microcredits，无退款。

| 变体                  | 终态/耗时            | 人工评分（身份/服装道具/场景/遵循/结构） |
| --------------------- | -------------------- | ---------------------------------------- |
| V1 正面与三分之二侧面 | succeeded · 约 69 秒 | 2/2/2/2/2 = **10/10**                    |
| V2 过肩与侧面反应     | succeeded · 约 91 秒 | 2/2/2/2/2 = **10/10**                    |
| V3 同场景情绪变化     | succeeded · 约 91 秒 | 2/2/2/2/1 = **9/10**                     |

合计 **29/30**，达到 24/30 门槛；没有发现换脸、严重肢体错误或场景完全漂移。V3 的最后一项
保守扣 1 分，是因为手机与手部有轻微遮挡、人物左右位置相对前两张发生变化，但不影响身份判断。
本轮产生了三次已结算图片请求；账户、任务、结果标识和远程资源链接不写入公开仓库。

这次通过的是“文本人物锚点 + 受控机位/情绪变化”回归，不等同于参考图驱动的生产级身份锁定：
当前 `openai-image` 发送的请求体只有 `model`、`prompt`、`size`，没有把上一张结果作为参考图输入。
在接入角色资产或参考图链路前，不应据此宣称跨镜头身份一致性已经完全解决；低价模型也暂不做
A/B 或向普通用户开放。
